# Локальная проверка бросков

Инструмент опубликован на GitHub Pages 17 сентября 2026 года. [Открыть программу проверки](https://volzay.github.io/online-backgammon/verify-game.html). Кнопки проверки также встроены в историю комнаты и админ-панели.

## Где открыть

В комнате, в блоке «Ход партии», у записи с SHA-256 есть кнопка «Проверить». Она сверяет конкретный бросок, не покидая доску. Ссылка «Подробнее» открывает отдельную программу с публичным хешем и костями. В раскрывающемся блоке «Проверка бросков» кнопка «Проверить все броски» проверяет всю доступную историю комнаты.

В админ-панели такие же кнопки есть в истории комнаты. Общая проверка работает именно с отображаемой партией: завершённым архивом, если он выбран, а не с текущим реваншем.

Ручная программа находится на странице `verify-game.html`. Вход в аккаунт для неё не требуется. Поддерживаются русский и английский языки, светлая и тёмная темы, мобильный экран.

## Что проверяет программа

Броски портала используют SHA-256, а не HMAC из приложенного образца. Сначала считается SHA-256 точной строки UTF-8:

```text
nardu|код комнаты|назначение броска|цвет|длина истории|счёт белых|счёт тёмных|время|номер переброса|случайное значение
```

Байты хеша читаются слева направо. Значения 252–255 пропускаются. Первые два допустимых байта дают кости по формуле `(байт % 6) + 1`. Дубль представляет две физические кости и четыре возможных перемещения; проверка не считает его четырьмя независимыми бросками. Для стартового броска сравниваются кости хоста и гостя в их исходном порядке.

Теперь для новых бросков сохраняется `sha256Input` — точная одноразовая строка, использованная в этом уже полученном броске. Она позволяет дополнительно проверить вычисление SHA-256. Она не является паролем, служебным токеном или seed для будущих бросков. Алгоритм генерации костей не изменён.

Результаты:

- «Совпадают» — сохранённая строка даёт указанный SHA-256, а кости соответствуют его байтам.
- «Несовпадение» — проверяемая строка, хеш или записанные кости не согласуются.
- «Неполная проверка» — данных недостаточно. У старых бросков исходная строка отсутствует: можно подтвердить только соответствие костей хешу. Отсутствующая или повреждённая запись не превращается в успешную проверку.

Редкий старый резервный путь генератора, когда в хеше меньше двух допустимых байтов, не воспроизводится через случайную догадку. Инструмент сообщает о невозможности такой проверки.

Совпадение **не доказывает** случайность генерации, отсутствие подбора хеша или публикацию обязательства до броска. Текущий портал не реализует независимый server-seed/client-seed commit–reveal протокол. Это также не проверка законности либо качества перемещений шашек: их правила остаются в `game.js`.

Раздел ручного HMAC из образца удалён 18 сентября 2026 года: портал не предоставляет необходимые для него Server Seed, Client Seed и Nonce. На странице оставлена только проверка фактического SHA-256-протокола портала.

## Обработка данных

Вычисления выполняются локально; проверка не меняет партию, рейтинг, архив или память бота. Введённые значения не отправляются, не сохраняются в хранилищах браузера и не попадают в URL. Ссылка на ручную программу передаёт только публичные хеш и кости через fragment. Неизвестные, повторяющиеся и чувствительные параметры отвергаются. Для SHA-256 нужен Web Crypto, обычно доступный по HTTPS или на localhost. При недоступности криптографии программа сообщает об ошибке, а не заменяет её случайной генерацией.

SQL-миграция и переустановка worker для этого инструмента не требуются. Игровой движок, веса сложного бота и его runtime digest не меняются.
