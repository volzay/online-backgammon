# Локальная проверка бросков

Инструмент встроен в исходники проекта. Публикация на действующем сайте — отдельный шаг; эта инструкция не означает, что новая версия уже развёрнута.

## Где открыть

В комнате, в блоке «Ход партии», у записи с SHA-256 есть кнопка «Проверить». Она сверяет конкретный бросок, не покидая доску. Ссылка «Подробнее» открывает отдельную программу с публичным хешем и костями. В раскрывающемся блоке «Проверка бросков» кнопка «Проверить все броски» проверяет всю доступную историю комнаты.

В админ-панели такие же кнопки есть в истории комнаты. Общая проверка работает именно с отображаемой партией: завершённым архивом, если он выбран, а не с текущим реваншем.

Ручная программа находится на странице `verify-game.html`. Вход в аккаунт для неё не требуется. Поддерживаются русский и английский языки, светлая и тёмная темы, мобильный экран.

## Что проверяет программа

Броски портала используют SHA-256, а не HMAC из приложенного образца. Сначала считается SHA-256 точной строки UTF-8:

```text
nardu|код комнаты|назначение броска|цвет|длина истории|счёт белых|счёт тёмных|время|номер переброса|случайное значение
```

Байты хеша читаются слева направо. Значения 252–255 пропускаются. Первые два допустимых байта дают кости по формуле `(байт % 6) + 1`. Дубль представляет две физические кости и четыре возможных перемещения; проверка не считает его четырьмя независимыми бросками. Для стартового броска сравниваются кости хоста и гостя в их исходном порядке.

Теперь для новых бросков сохраняется `sha256Input` — точная одноразовая строка, использованная в этом уже полученном броске. Она позволяет дополнительно проверить вычисление SHA-256. Она не является паролем, служебным токеном или seed для будущих бросков. Алгоритм генерации костей не изменён.

Результаты:

- «Совпадают» — сохранённая строка даёт указанный SHA-256, а кости соответствуют его байтам.
- «Несовпадение» — проверяемая строка, хеш или записанные кости не согласуются.
- «Неполная проверка» — данных недостаточно. У старых бросков исходная строка отсутствует: можно подтвердить только соответствие костей хешу. Отсутствующая или повреждённая запись не превращается в успешную проверку.

Редкий старый резервный путь генератора, когда в хеше меньше двух допустимых байтов, не воспроизводится через случайную догадку. Инструмент сообщает о невозможности такой проверки.

Совпадение **не доказывает** случайность генерации, отсутствие подбора хеша или публикацию обязательства до броска. Текущий портал не реализует независимый server-seed/client-seed commit–reveal протокол. Это также не проверка законности либо качества перемещений шашек: их правила остаются в `game.js`.

## Ручной HMAC из образца

Отдельный закрытый раздел воспроизводит описанную в образце схему:

```text
key = UTF-8(serverSeed)
message = gameId:clientSeed:nonce
digest = HMAC-SHA256(key, message)
```

Он умеет сверять раскрытый Server Seed с его SHA-256, считать HMAC, показывать исходные байты костей и сравнивать записанный результат. Необязательный «Ожидаемый HMAC-SHA256» относится к HMAC конкретного броска, а не к SHA-256 Server Seed. Nonce — безопасное неотрицательное целое число; дробные, экспоненциальные и неоднозначные записи отклоняются.

Эта схема не подменяет алгоритм текущего портала. Её отсутствующие поля нельзя восстановить из старых архивов.

## Обработка данных

Вычисления выполняются локально; проверка не меняет партию, рейтинг, архив или память бота. Введённые значения не отправляются, не сохраняются в хранилищах браузера и не попадают в URL. Ссылка на ручную программу передаёт только публичные хеш и кости через fragment. Неизвестные, повторяющиеся и чувствительные параметры отвергаются. Для SHA-256/HMAC нужен Web Crypto, обычно доступный по HTTPS или на localhost. При недоступности криптографии программа сообщает об ошибке, а не заменяет её случайной генерацией.

SQL-миграция и переустановка worker для этого инструмента не требуются. Игровой движок, веса сложного бота и его runtime digest не меняются.

## Проверка реализации

17 сентября 2026 года прошли 93 теста инструмента: криптографические векторы SHA-256/HMAC, точные UTF-8 значения, открывающий бросок и дубли, повреждённые и отсутствующие записи, ограничения ввода, безопасные ссылки, сохранение исходной строки реальным генератором и защита от устаревшего асинхронного результата. Тесты подтверждают корректность проверки данных, а не честность самого генератора.

Команда для повторения:

```sh
node --test tests/game-verifier.test.js tests/game-verifier-integration.test.js tests/roll-verification-ui.test.js
```

Дополнительно прошли 35 существующих целевых тестов комнаты, админ-панели, снимков состояния и жизненного цикла. Сборка GitHub Pages включает все шесть новых статических файлов и обновляет версии ресурсов.

В настоящем браузере проверены отдельная программа на экранах 375×812 и 390×844, оба языка и обе темы. Встроенные элементы комнаты и админ-панели дополнительно проверены на локальном тестовом примере при ширине 375 px: полный результат, частичный результат старого броска и несовпадение в архиве отображаются раздельно; горизонтального переполнения нет. Для этой проверки аккаунты и действующие игровые комнаты не использовались.

Полный прогон проекта на Node.js 24.15.0 / macOS завершён 17 сентября: 978 тестов, 967 успешных, 0 ошибок, 11 пропусков Linux-специфичных тестов. SHA-256 всех 117 файлов проверяемого функционального набора одинаковы до и после прогона, а также после финальной сборки. Playing policy и worker runtime digest остались прежними. Команда полного прогона — `npm test` (в отчёте дополнительно включён текстовый reporter).
