# Экспериментальная нейросеть для длинных нард

Создана отдельная небольшая сеть оценки позиций, а не языковая модель. Она работает только с
длинными нардами и не включена вместо сложного бота на production. Файлы существующего
движка и идентификатор действующей политики сохранены, защищённый генератор бросков не меняется.
В диспетчер и лобби добавлен отдельный экспериментальный вариант `hard-neuro`.

## Отдельный бот на портале

В лобби: «Играть с ботом» → «Длинные нарды» → **«Сложный бот-нейро»**.
Для коротких нард он недоступен. Обычный «Бот сложный» работает как прежде.
Рейтинг 1500 — техническое номинальное значение, не измерение силы этой модели.

`long-neural-bot.js` использует только сохранённую модель `hard-neuro-448-v1`:
448 завершённых учебных партий, 35 147 обновлений, выбор не более 16 вариантов,
`epsilon: 0`. Нет онлайн-градиентов, случайной инициализации или общей памяти старого hard.
При отсутствии/ошибке модели партия приостанавливается с понятным сообщением; скрытая
подмена на эвристику, случайный или обычный сложный бот запрещена. Кубики по-прежнему
выдаёт независимый от нейросети существующий механизм защищённых бросков.

Публичный файл `vendor/long-neural/model.json` содержит только веса и метаданные.
Сборщик `scripts/build-long-neural-model.js` проверяет отпечатки модели, правил и кода,
создаёт замороженный браузерный `model.js`; обычная CI-сборка не требует приватного `data/`.
Первый экспорт полного учебного артефакта проверяет его происхождение, а не только JSON весов.

История игры, `analysis.neuralModel` и последние 180 `analysis.neuralDecisions` сохраняются
отдельно от `analysis.botMemory` и v35 XP. Запись содержит исходную видимую позицию,
выпавшие кости, выбранные ходы, оценку сети, отпечаток модели и реально выполненную
последовательность. Завершённые партии попадают в существующий архив final_state.
Это материал для последующего офлайн-разбора, **не автоматическое обучение на портале**:
архив имеет существующий срок хранения (по умолчанию 96 часов) и не является постоянным
учебным хранилищем. Для очередного обучения игры нужно экспортировать до очистки архива.

Кандидат добавлен для совместной экспериментальной игры по запросу пользователя;
его результат 62,2% относится только к описанному ниже синтетическому контролю.
Строгий исследовательский допуск и доказанный процент побед против людей не достигнуты.

## Устройство

`lib/long-bot-neural.js` экспортирует `NarduLongNeural` в браузере и CommonJS API для Node.js.
Сеть состоит из 127 входных признаков, скрытого слоя с `tanh` и одного выхода с `sigmoid`.
По умолчанию скрытый слой содержит 32 нейрона; формат ограничивает его 128 нейронами.
Веса и архитектура хранятся в строгом JSON-формате `nardu-long-neural-value-v1`.

Признаки описывают расположение и количество шашек относительно цвета игрока, снятые шашки,
очерёдность, текущие уже выпавшие кубики, фазу и контекст первого хода. Позиции коротких нард,
неправильное число шашек, несовместимые размерности и нечисловые/чрезмерные веса отклоняются.

Движок `game.js` формирует законные полные последовательности ходов с соблюдением правил
головы, блока из шести, использования кубиков и снятия шашек. Нейронный бот воспроизводит
их через этот же движок, оценивает позиции **после окончания хода** и выбирает лучшую.
Он не изменяет кости, не видит будущих бросков и не исполняет JavaScript из загруженного файла.

Число оценённых вариантов ограничено `maxCandidates`. При избытке законных последовательностей
берётся равномерная выборка из списка, отсортированного относительно маршрута действующего
цвета, а не только первые варианты. При обмене цветов и повороте доски выборка и политика
совпадают; это проверяется отдельным тестом. `getLastDecision()` сообщает покрытие и признак усечения. Это ограниченный поиск
по продолжениям одного собственного хода, а не уже готовый многоходовый поиск ответов соперника.
Законный вариант немедленной победы включается даже при усечении выборки и имеет безусловный
приоритет перед нетерминальной оценкой сети. Учебное исследование альтернатив не заменяет
такую победу случайным ходом.
Выход сети в диапазоне 0–1 обучается как оценка выигрыша; без калибровки его нельзя выдавать
за доказанную вероятность победы.

## Самообучение

`scripts/train-long-bot-neural.js` обучает модель офлайн против замороженной копии самой себя и
трёх простых соперников: случайного, ориентированного на пипсы и жадного по продвижению.
В начале каждой партии веса фиксируются для обоих игроков. Исследование альтернатив применяется
только в учебных матчах; оно использует отдельный явно заданный псевдослучайный поток.

Обучение использует эпизодические цели TD(λ), рассчитываемые только после завершения партии.
При λ = 0 оценка последующей позиции того же цвета служит целью для предыдущей;
для последней нетерминальной позиции цель равна фактическому исходу. Промежуточное λ смешивает
один шаг замороженной оценки и накопленный возврат последующих состояний. При λ = 1 каждая
нетерминальная позиция получает фактический исход всей партии — режим Monte Carlo.
Цели рассчитываются из замороженной модели, затем веса обновляются
обратным распространением ошибки. В самоигре обучаются обе стороны, против простого соперника
по умолчанию — только нейронный кандидат; `--learn-colors both` добавляет позиции соперника.
Сама терминальная позиция имеет точный результат по правилам и не
используется как обучаемый выход сети.

Превышение лимита ходов или времени не считается ничьей, победой или полезным обучающим
результатом: незавершённый эпизод отклоняется. Прерванный запуск не выдаёт завершённость за
все запрошенные игры. Сохранённый контрольный файл может содержать только уже завершённые
эпизоды; его статус должен отличать выполненное число игр от запрошенного.

Накопительный формат `long-neural-training-artifact-v2` сохраняет цепочку учебных сегментов:
предыдущий артефакт и модель, параметры, λ, потоки кубиков, число завершённых партий и
обновлений каждого сегмента. При продолжении обучения проверяются строгая модель,
совместимость правил и кода вычислений, целостность этой цепочки и отсутствие повторных
потоков. Возобновление не должно обнулять происхождение или выдавать старые эпизоды за новые.
Ранняя оболочка `v1` остаётся отдельным историческим форматом TD(0).

## Запуск обучения и независимой проверки

Из корня проекта создайте отдельный каталог результатов. Пути `--output` должны быть абсолютными,
родительский каталог должен существовать. Повторный запуск может заменить указанный файл:
для нового кандидата выбирайте новый каталог или имя.

```sh
neural_run_dir=$(mktemp -d /private/tmp/nardu-long-neural.XXXXXX)
node scripts/train-long-bot-neural.js \
  --games 64 --seed 236049 --hidden-size 32 \
  --max-candidates 16 --max-plies 640 \
  --max-game-ms 30000 --max-elapsed-ms 120000 \
  --epsilon 0.1 --learning-rate 0.01 \
  --lambda 0 --checkpoint-every 16 \
  --opponents self,random,pip,greedy \
  --output "$neural_run_dir/candidate.json"
node scripts/evaluate-long-bot-neural.js \
  --model "$neural_run_dir/candidate.json" \
  --pairs 32 --seed 237073 --max-candidates 16 \
  --opponents random,pip,greedy,current-hard \
  --max-plies 640 --max-game-ms 30000 --max-elapsed-ms 600000 \
  --output "$neural_run_dir/evaluation.json" --require-gate
```

Это пример ограниченного запуска, не обещание уложиться в указанный бюджет: если он недостаточен,
процесс завершится с ошибкой без зачёта неполных результатов. `--help` показывает справку.
Для проверки только технической работоспособности допустимы меньшие `--games` и `--pairs`,
но малый запуск не сертифицирует силу модели. `--require-gate` возвращает ненулевой код,
если статистический порог не достигнут.

Для продолжения совместимого учебного артефакта используйте отдельный выходной файл:

```sh
node scripts/train-long-bot-neural.js \
  --resume "$neural_run_dir/candidate.json" \
  --games 128 --seed 236049 --lambda 1 --checkpoint-every 16 \
  --max-candidates 16 --max-plies 640 \
  --max-game-ms 30000 --max-elapsed-ms 600000 \
  --epsilon 0.1 --learning-rate 0.01 \
  --opponents self,random,pip,greedy \
  --output "$neural_run_dir/candidate-continuation.json"
```

`--games` при продолжении означает **дополнительные** завершённые партии, не общий итог.
При том же базовом seed индекс потоков автоматически начинается после уже использованного
максимума; новый seed допустим только без совпадений потоков. λ = 0 оставляет исходный TD(0),
λ = 1 применяет цели Monte Carlo. `--checkpoint-every` задаёт сохранение по завершённым
эпизодам; текущий незавершённый эпизод не включается в модель и журнал.

Ранее раскрытые проверочные потоки можно явно исключить из следующего обучения параметром
`--forbidden-dice-seeds` с отдельным файлом их списка. При выборе параметров по результатам
повторных матчей этот набор становится валидационным, а не новым независимым тестом.
Финальное заявление о проценте побед требует зафиксировать модель и условия до проверки
на ещё не использованных контрольных потоках; нельзя подбирать удачный seed задним числом.

Кандидат сохраняется в известной учебной оболочке `long-neural-training-artifact-v1` либо
накопительной `long-neural-training-artifact-v2`: строгая модель находится
в поле `model`, журнал и параметры — в `trainingManifest` и `results`. Отпечатки связывают
веса, правила и код вычислений. Проверяющий скрипт сверяет их, завершённость партий,
число обновлений и список учебных потоков. Эти локальные отпечатки позволяют обнаружить
изменение файла, но сами по себе не являются подписью независимого автора или сертификатом силы.

Проверка использует другой домен потоков кубиков и отклоняет совпадения с учебными потоками.
Кандидат в ней не обучается и не исследует случайные альтернативы. Для каждой пары выполняются
две партии с обменом цветов на одинаковых потоках белого и тёмного места.

Порог 65% проверяется **только против определённого набора соперников**, отдельно для
каждого. Помимо `random/pip/greedy` проверяющий скрипт поддерживает `current-hard` — замороженный
действующий сложный бот с пустой памятью опыта, точным текущим диспетчером и неизменными весами
политики. Это локальная контрольная копия, не игрок в реальной комнате. Отказ, подмена
метаданных или переход контрольного бота на запасной алгоритм прерывают проверку.

Нужны минимум 30 полных пар на соперника и нижняя односторонняя граница
Хёффдинга не ниже 0,65. Единица независимости — целая пара; поправка Бонферрони учитывает
несколько соперников. Интервал Уилсона в отчёте лишь описательный: две партии одной пары
зависимы, поэтому он не решает вопрос допуска. Даже 65% наблюдаемых побед может быть
недостаточно для прохождения порога.

`poolGatePassed` показывает результат для выбранного набора. Без `current-hard` даже победа
над всеми простыми соперниками остаётся диагностикой: итоговый `gatePassed` всегда `false`.
Для итогового порога нужно включить `current-hard` и пройти статистическое условие против
каждого выбранного соперника.

Даже успешно прошедший контрольный набор файл сохраняет `productionEligible: false`.
Потребуются дополнительные матчи против разнообразных сильных
стратегий и откалиброванных по человеческой игре соперников, проверки ключевых ошибок
и задержки. Результат против простых ботов не переносится автоматически на людей или турниры.

## Браузерная лаборатория

`experiments/long-neural/index.html` — отдельная офлайн-страница для осмотра модели и ходов.
Она загружает только движок правил, нейронный модуль и собственные файлы демонстрации,
не импортирует клиентов авторизации или комнат и не отправляет результаты по сети.
В сборку GitHub Pages и обычное игровое меню она не добавлена.

```sh
node scripts/serve-long-bot-neural-demo.js --port 3909
```

Откройте `http://127.0.0.1:3909/experiments/long-neural/index.html`. Сервер привязан только
к loopback и разрешает пять конкретных публичных файлов стенда; API, каталог проекта,
файлы учётных записей и произвольные пути недоступны. Политика страницы запрещает сетевые
подключения, формы с отправкой и сторонние скрипты. После работы остановите сервер `Ctrl+C`.

Загрузите JSON-модель или учебный артефакт `v1`/`v2`. Браузер извлекает только строгие веса,
а накопительный журнал не считает доказательством силы или подлинности обучения.
До проверки размера и строгой схемы выбор хода
отключён. Файлы больше 2 МиБ, повреждённый JSON и несовместимые веса отклоняются; неудачная
замена также выключает ранее загруженную модель. Нулевое число обучающих обновлений явно
помечается как **необученная случайная инициализация**. Манифест загруженного файла считается
данными его автора, а не проверенным происхождением.

Накопительный файл с большим журналом может превысить 2 МиБ. В этом случае стенд отклонит
его целиком; можно осматривать отдельно сохранённое поле `model` в том же строгом формате.
Число обновлений больше нуля тоже не означает, что модель готова заменить production-бота:
стенд всегда сообщает, что сила игры не сертифицирована.

На стенде кубики задаются вручную, дубль расширяется до четырёх значений. Это исключительно
синтетические учебные броски, не броски реальных комнат. Можно осмотреть выбранные законные
ходы и оценку сети, применить их к учебной доске и задать следующий бросок для другой стороны.
Все изменения происходят локально; перед применением весь ход проверяется движком правил.

## Продолжение обучения: первый порог 50%

Продолжение начинается с этих 64 партий и их сохранённых весов, не со случайной
инициализации. `--sample-order seeded-shuffle` перемешивает уже рассчитанные по
замороженной сети целевые значения отдельным воспроизводимым потоком; поток кубиков
от этого не меняется. `--learn-colors both` использует не только позиции нейробота,
но и позиции его соперника из той же завершённой партии. Это обучение критика по
смешанным поведенческим политикам, а не гарантия роста процента побед.

Перед продолжением зафиксирован протокол
`data/long-neural/milestone50/protocol.json`: равные доли `random/pip/greedy`,
16 оцениваемых последовательностей, максимум 640 ходов. Разработка использует
seed 410099 и четыре пары на соперника. Эти результаты разрешено использовать
для выбора модели, поэтому они **не независимый финальный тест**.

Для единственной финальной проверки сохранённой, выбранной модели зарезервирован
seed 420099: 30 пар со сменой цветов на каждого соперника, всего 180 партий.
Будущие контрольные потоки и ранее использованные контрольные броски исключены
из обучения файлом `reserved-dice-seeds.json` — JSON-массивом уникальных ненулевых
32-битных seed. Резервации наследуются при возобновлении.

```sh
node scripts/evaluate-long-bot-neural.js \
  --model /absolute/frozen-candidate.json \
  --protocol /absolute/protocol.json \
  --purpose development-validation \
  --output /absolute/validation.json
```

Для финального запуска выбирается `--purpose held-out-confirmation`.
`researchMilestonePassed` означает, что нижняя односторонняя 95%-я граница
Хёффдинга для средней доли побед по всему заранее заданному, сбалансированному
набору не ниже 0,50. Это отдельный исследовательский порог: он не требует
50% против каждого соперника, не заменяет строгий порог 65% и не оценивает
победы над игроками портала. Результаты настройки, одна лишь наблюдаемая доля
50%, недостаточный размер выборки или незавершённые партии этот порог не дают.
CLI оставляет журнал использования финального протокола и отклоняет его
повторное использование после завершения или прерванной попытки.

### Память завершённых учебных партий

Для следующих этапов добавлен необязательный терминальный replay:
`--lambda 1 --replay-games 32 --replay-samples 64`. Сохраняются не более 32
последних завершённых партий, до 64 состояний на каждую. Дополнительные 64
обновления на новую завершённую партию используют только предыдущие партии,
поровну выигрышные и проигрышные позиции, с отдельным воспроизводимым RNG.
Новые и повторные примеры перемешиваются параметром `--sample-order seeded-shuffle`.

Файл хранит источник каждого примера, его состояние, терминальную цель,
отпечатки исходной трассы и состояния и журнал повторных обновлений. Проверка
восстанавливает допустимое скользящее окно, связывает настройки с сегментом,
сверяет снятые шашки победителя/проигравшего и точное число градиентных шагов.
Модель, счётчики, результат и память публикуются одним завершённым шагом;
ошибка метаданных после градиента тоже не сохраняет половину обновления.

Существующая память и её настройки наследуются при продолжении. Явное
отключение replay у файла с памятью отклоняется до первой партии. У старых
кандидатов без сохранённых позиций память начинается пустой: доски их
исторических партий не придумываются. Повторное обучение не увеличивает
число независимых партий, только `trainingSamples`/`trainingSteps`.

Зафиксированный для первого финального контроля кандидат имеет 448 учебных
партий и 35 147 обновлений. Он обучался ещё **без replay**; включение этой
добавленной памяти относится к следующим кандидатам, не меняет его контрольные
результаты. Его веса отдельно сохранены в `model-frozen.json` для загрузки
в браузерный стенд без большого журнала обучения.

### Совместимость оптимизированного поиска с сохранёнными весами

Для устранения замедления к концу партии внутренние симуляции правил больше
не копируют полную историю на каждом узле поиска. Публичные снимки,
реально применённые ходы, сохранённые доказательства бросков, веса и стратегия
нейробота не меняются. Эта оптимизация не является новым обучением или повторной
оценкой силы: 448 учебных партий, 35 147 обновлений и прежние 112/180 побед
относятся к исходному измеренному кандидату.

`metadata.rulesFingerprint` сохраняет именно исходный SHA обучавшегося и
проверенного `game.js`:
`sha256:769c571ad10cefa75a8c128aba5123df47684780fad1136a0ae98f3342f33e4b`.
Отдельный `runtimeRulesFingerprint` указывает оптимизированный источник:
`sha256:6561996b3d148e0a10a972347474c7be4332a891437e3d6565d36020f7520623`.

В отдельном paired-rollout cache закреплены два полных audited tuple (game SHA,
bundle SHA и policy implementation ID): исходный и оптимизированный. Смешанные
или неизвестные tuple не используют cache; namespaces двух версий различны.
Сгенерированный обычный v35 bundle сохраняет истинный source-derived
`policyImplementationId`; он включает байты `game.js` и wrapper. Dispatcher,
ресурсы и веса не меняются. Отдельный `learningPolicyImplementationId` разрешает
уроки исходного `fcdc…` только через immutable metadata со схемой
`long-v35-history-free-learning-compat-v1`. Сборщик проверяет точные SHA всех
восьми source preimages, включая финальный wrapper; изменение одного байта
убирает alias. Единый predicate принимает текущий actual ID либо этот audited
alias в live RPC и восстановлении frozen session. Исходные pattern IDs,
aggregate IDs, runtime digests и fingerprints не переписываются; новый frozen
snapshot отдельно записывает actual ID и actual source fingerprints. Фабрика
`current-hard` допускает два точных runtime tuple. Это разрешение
совместимости не меняет исторических отчётов и не ослабляет правила provenance:
trainer/evaluator по-прежнему отвергают resume или новую оценку исходного
saved448 artifact на иных training rules bytes. Для нового benchmark требуется
отдельный явно оформленный переход provenance или исходный frozen runtime.
Поле `rulesCompatibility: history-free-rule-search-v1` обозначает ограниченную
совместимость этих двух конкретных исходников. Сборщик допускает только эти
два SHA, проверяет соответствие публичного asset фактическому исходнику и
отклоняет любые неизвестные версии. Исторические метаданные обучения не
переписываются и не выдаются за новую контрольную выборку.

`tests/game-search-history-performance.test.js` проверяет точный порядок
законных и ограниченно выбранных последовательностей на 24 позициях обоих
видов нард и цветов, полные реальные переходы состояния, сохранность
1200 архивных доказательств и нулевое число их копирований внутри поиска.
На шести позициях также совпадают планы и оценки именно опубликованных
обученных весов при прежних cap16 и ε=0. Это проверка совместимости,
не дополнительная статистика побед и не гарантия силы против игроков.
