# Обучение на проверенных позициях проигранных партий

Причины отсутствия опыта в проверке 22 ноября 2026:

- задания 8JPN-KUD8 (2401) и CTNM-E43Z (2402) не получили ни одного вычислительного среза;
- у LEM5-RES8 в `room_game_archives` есть полный журнал, но в `bot_training_games` нет записи, а исходные решения удалены из компактного состояния;
- новая игровая версия получает только собственные причинно подтверждённые уроки. Старые проигрыши не становятся её заданиями автоматически;
- причинный контур требует полных сравнительных доигрываний и нижней границы улучшения более 0,08. Сам проигрыш и эвристическая оценка не являются таким доказательством.

Новый независимый контур читает `room_game_archives`, восстанавливает каждый ход по правилам, проверяет максимальное использование костей и совпадение конечной доски. Он не восстанавливает отсутствующие исходные оценки или подписи. Для LEM5-RES8 воспроизводятся все 42 хода бота.

Учитель заново вычисляет выбор текущей холодной политики. Для позиций с 2–64 различными законными результатами он сравнивает каждый результат на всех 21 вариантах костей противника с весом 36. Ответы противника использует именованная ограниченная модель `best-of-bounded-legal-replies-v1`. Сохраняется совет с улучшением модельной оценки и полезности не менее 0,025, ограничением ухудшения нижнего хвоста 0,06, сохранением непосредственной безопасности результата и проверкой фактического изменения законного выбора движка.

Это **модельный урок**, а не статистическое подтверждение вероятности победы. Формат `creditVersion:10` явно содержит `terminalOutcomeConfirmed:false`, `scoreSemantics:heuristic-turn-equity-v1`, исходный архив, его хеш, старую политику, текущую политику, исходный ход, холодный ход и рекомендуемый ход. Модельные уроки не записываются в `long_bot_causal_evidence`, не изменяют прежние пороги и не подменяют счётчик причинно подтверждённых уроков.

Движок применяет совет только при точном совпадении доски, костей, флагов правил и исходного холодного решения. Необходимые проверки безопасности сохраняются. Причинно подтверждённые поправки имеют приоритет. Опыт замораживается на партию; изменения с сервера вступают в силу в следующей партии. Телеметрия выбранного хода содержит `boardModelLesson`, идентификатор урока и обе оценки сторон.

Отдельный сервис сохраняет прогресс после каждой позиции, чередует комнаты по числу разобранных ходов и продолжает после перезапуска. Повреждённый журнал помещается в карантин. После завершения трёх приоритетных комнат автоматически обрабатываются остальные проигрыши. Действующие архивы, исходные решения, подписи и причинные очереди не переписываются.

## Завершение проверки 23 ноября 2026

Для запрошенных партий исходный контур сохранил 7 модельных уроков из LEM5-RES8 (42 хода), 3 из 8JPN-KUD8 (38) и 1 из CTNM-E43Z (44). Сам курсор 124/124 не доказывает полную оценку: два хода CTNM имеют 172 и 80 различных результатов, больше старого предела 64. Отдельный диагностический запуск `audit-long-bot-board-turns.js` заново проверяет все 124 позиции с пределом 256 и сохраняет статус каждой позиции; capacity не считается завершённым анализом. Он ничего не записывает в серверную статистику.

Две новые реальные партии NGKR-DZWK и NEKP-JRTV показали ограничение точных уроков: загрузка опыта была успешной, но ни один из 100 ходов не применил урок. Поэтому политика `7a263bcd…` добавляет перенос опыта: сопоставляет фазу и близкие позиционные признаки и использует изменения семантических признаков урока, чтобы предложить не более двух текущих законных результатов. Затем заново сравнивает исходный ход и предложения на всех 21 вариантах костей соперника. Выбор меняется только при улучшении текущих модельных equity и utility не менее 0,025, с ограничением ухудшения хвоста и прежними проверками безопасности. Дополнительный бюджет явный: максимум 63 первичных ответа сверх исходных 480/58. Это модельная оценка, не вероятность победы, доказанная доигрываниями.

Существующие уроки сохраняют исходные policy/runtime/aggregate ID. Разрешение совместимости касается только модельных советов `creditVersion:10`; прежние терминальные доказательства `creditVersion:9` не получают алиас новой политики. Серверный мост разрешает только точный исходный runtime `5a0d17b5…`, клиентский мост исчезает при изменении любого исходного файла политики или правил. Загруженный опыт по-прежнему заморожен на партию.

Аудит нулевой статистики: 232 полных старых проверки использовали по 32 доигрывания на вариант; максимальное наблюдаемое преимущество 0,28125, наибольшая сохранённая нижняя граница −0,2616661349. Все эти проверки статистически неопределённы. Статус legacy `no-regret` не является доказательством отсутствия лучшего хода; новый диагностический вывод явно содержит `statisticalConclusion:inconclusive`. Даже оптимистичная верхняя оценка парного betting-теста по наблюдаемым маргинальным результатам достигает лишь 0,07942 требуемого порога. Это диагностическая оценка мощности, а не восстановленные пары и не основание публиковать урок. Метод опирается на [Waudby-Smith & Ramdas, 2024](https://academic.oup.com/jrsssb/article/86/1/1/7043257). Порог подтверждения не снижен.

Старая очередь всегда отдавала абсолютный приоритет наиболее продвинувшейся focused-задаче. Исправление вводит отдельный транзакционный билет для чередования focused/обычной работы; среди focused выбирается самое давнее обслуживание. Проверка реальной SQL-функции с откатом выдала 2401, 2383, 2402: обе запрошенные исходные задачи получили бы время, обычная очередь также сохранила доступ. Диспетчер выделяет исходному runtime d7fd два из 13 десятиминутных слотов в прежних CPU/памяти/времени сервиса, сохраняя все исторические ветви и журналы.

Обновлённый серверный учитель допускает до 256 результатов (предел закреплён отдельно для каждого runtime), сохраняет квитанцию каждого хода и при исчерпании ресурсов оставляет позицию ожидающей, вместо продвижения курсора. Старые 64-вариантные релизы не получают расширение автоматически. Новый проход получает отдельный runtime и собственный курсор; прежние архивы и 11 уроков остаются неизменными.
