# Быстрые проверяемые броски — v37

Протокол `system-csprng-v1` добавляет собственный генератор без RANDOM.ORG, оплаты или API-ключа. Он предназначен для новых комнат. Протокол уже созданной комнаты неизменен; прежние доказательства drand проверяются по прежним правилам.

## Как получается бросок

1. PostgreSQL под блокировкой комнаты создаёт 32 случайных байта через `extensions.gen_random_bytes(32)` и сохраняет секрет в закрытом журнале. Номер, партия, позиция и SHA-256 обязательства фиксируются единожды.
2. Координатор подписывает обязательство существующим ключом Ed25519. Браузер проверяет подпись и контекст, затем создаёт собственные 32 байта через `crypto.getRandomValues()`. Обязательство и вклад сохраняются в браузере до отправки.
3. Сервер сохраняет первый принятый вклад и вычисляет HMAC-SHA256. Байты 252–255 пропускаются; первые два допустимых байта дают кости `(байт % 6) + 1`. Обычные дубли сохраняются; ничья стартового броска разрешается первым допустимым детерминированным счётчиком.
4. Секрет раскрывается только после сохранения вклада. PostgreSQL и браузер независимо пересчитывают обязательство, поток и кости. Бот выбирает ходы, но не передаёт выбранные кости. Для броска бота случайный вклад также создаёт браузер человека.

Повторные запросы и рестарт продолжают ту же запись. Подмена сохранённого клиентского вклада, пропуск номера, смена протокола или выдача нового секрета вместо неудачного результата запрещены. После неопределённого ответа браузер сохраняет прежний вклад. При его несовпадении с сервером проверка останавливается. Другой браузер без собственной записи может восстановить первый принятый вклад, но не получает утверждение, что сам создал его.

Источники: [PostgreSQL pgcrypto](https://www.postgresql.org/docs/17/pgcrypto.html), [Web Crypto getRandomValues](https://developer.mozilla.org/en-US/docs/Web/API/Crypto/getRandomValues).

## Что подтверждает проверка

Успешный статус: «Подпись и расчёт броска подтверждены». Проверяются закреплённая серверная подпись, раскрытый секрет, SHA-256 обязательства, HMAC-SHA256 и записанные кости. Полное публичное JSON-доказательство доступно в подробностях броска. Один конечный SHA-256 — контрольная сумма протокола, а не исходный поток для костей.

Это собственный серверный CSPRNG, **не независимый внешний источник**. Подпись сервера не доказывает физическую случайность одного броска или независимое время публикации. Клиентская запись позволяет участнику сверить ранее полученное обязательство и собственный вклад. Экспортированный JSON без этой записи подтверждает внутреннюю согласованность, но не её предварительное получение. Система не устраняет возможность оператора прекратить обслуживание; журнал сохраняет отменённые/незавершённые записи, а известные кости нельзя перебросить.

## Реализация и выпуск

- SQL: `supabase/fair-dice-v37.sql`; база сама проверяет HMAC и сохраняет закрытую энтропию. Новые поля добавляются без переписывания старых партий.
- Координатор: `lib/fair-dice-service.js`, маршрут `/challenge`; приватный seed доступен только service-role. Обычный игрок должен подтвердить действующую гостевую/зарегистрированную сессию и право на этот бросок.
- Клиент: `rooms-client.js`, `fair-dice.js`, локальный криптографический bundle. Нет `Math.random`, внешнего API или fallback между источниками.
- Изолированная CLI-программа в `experiments/system-dice` остаётся демонстрацией протокола; её файловый журнал не используется production.

Миграция сама **не активирует** новый default. До активации обязательны проверенная резервная копия, реальный PostgreSQL smoke в единой транзакции с `ROLLBACK`, полный набор тестов, dual-protocol координатор, четыре контролируемые HTTPS canary-комнаты и публикация совместимого клиента с прежним настоящим ключом.

Для smoke: `node ops/timeweb/emit-system-fair-dice-smoke.js` → `psql -v ON_ERROR_STOP=1`. Canary fixtures с `--protocol system-csprng-v1 --preserve-policy` создаются в одной транзакции с восстановлением исходных defaults до COMMIT. Реальные комнаты игроков не используются для тестовых ходов.

После проверок default меняется через service-only `configure_fair_dice_protocol('system-csprng-v1')`; protection остаётся включённым. Откат default — `configure_fair_dice_protocol('drand-quicknet-v1')`, **с сохранением dual-protocol координатора и клиента** для начатых system-комнат. Не восстанавливать старый dump поверх действий игроков и не понижать защиту их комнат.

Анимация нового протокола — 380 мс. Цель полного броска ≤2 секунды должна проверяться через настоящий HTTPS; локальные замеры CLI не являются production latency/SLA. Финальные результаты выпуска фиксируются отдельно после активации.
